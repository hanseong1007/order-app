# (주)경덕농수산 거래처 발주 화면

거래처에 납품할 품목을 **휴대폰에서 바로 골라 담고**, 발주서를 카톡·문자로 보내거나 엑셀(CSV)로 저장하는 단일 파일 웹앱입니다.
**직원별 로그인**(관리자 + 직원 계정), **바코드를 연속으로 찍어 담기**(끊김 없이 계속 스캔), **담긴 품목만 모아 수량 직접 입력**, **거래처별 품목 관리**, **엑셀 붙여넣기 대량 등록**, **거래처별 지난 발주 수량 한 번에 불러오기**, **같은(공통) 바코드 후보 1탭 선택**까지 됩니다.
설치할 것도, 서버도 없습니다. `index.html` 파일 하나만 있으면 됩니다. **품목 828개는 암호화되어 들어 있어** 로그인해야 볼 수 있습니다(아래 2-4).

- 파일: `index.html` (약 277KB, 외부 라이브러리 없이 동작 · 품목 828개가 암호문으로 들어 있음)
- **관리자 계정은 이 기기에 하나만** 있습니다. 처음 관리자 비밀번호는 **화면에 나오지 않습니다** — 초기 암호는 관리자에게만 따로 전달되고, 로그인 뒤 `내 계정`에서 바로 바꿔 쓰세요(2번 참고).
- 화면 예시는 **예시용 가짜 품목**으로 찍었습니다(실제 품명·바코드는 나오지 않습니다): `screenshot-1-catalog.png` · `screenshot-2-photo.png` · `screenshot-3-summary.png` · `screenshot-4-barcode.png` · `screenshot-5-items-bulk.png` · `screenshot-6-ordered-qty.png`(담긴 품목만+수량 입력) · `screenshot-7-scan-live.png`(연속 스캔) · `screenshot-8-photo-next.png`(사진으로 찍을 때 · 다음 바코드 찍기) · `screenshot-9-login.png`(로그인 화면) · `screenshot-10-admin-users.png`(관리자 · 사용자 관리) · `screenshot-11-last-order.png`(거래처별 지난 발주 불러오기 · 지난번 N개) · `screenshot-12-barcode-pick.png`(같은 바코드 후보 · 1탭 선택) · `screenshot-13-share-order.png`(찍은 차례대로 정렬된 발주서) · `screenshot-14-share-text-barcode.png`(공유 글의 `품목 (규격)_바코드 7·2·4`)

## 1. 휴대폰에서 여는 방법

### 방법 A — 파일로 받아서 쓰기 (인터넷 없이 사용)

1. `index.html` 파일을 휴대폰으로 받습니다. (카톡 ‘나에게 보내기’ → 파일 저장, 또는 메일 첨부)
2. 파일 관리자(내 파일)에서 `index.html`을 눌러 **Chrome으로 열기**를 선택합니다.
   - 주소창에 `file:///.../index.html`로 표시됩니다.
   - 이 상태에서도 발주서 작성·복사·CSV 저장·발주 내역 저장·사진 바코드 읽기가 모두 됩니다.
   - 다만 `file://`에서는 브라우저가 **카메라 실시간 화면을 막는 경우가 있습니다**(아래 5번 참고). 그때는 ‘사진으로 바코드 읽기’(여러 장도 가능)나 번호 직접 입력을 쓰세요.
3. Chrome 메뉴(⋮) → **홈 화면에 추가**를 누르면 아이콘이 생겨 다음부터 한 번에 열립니다.
   (파일로 열었을 때는 ‘북마크 바로가기’로 추가됩니다.)

### 방법 B — 인터넷 주소로 올려서 쓰기 (여러 직원이 같이 쓰기 좋음)

Netlify Drop(<https://app.netlify.com/drop>) 같은 무료 호스팅에 `index.html`을 끌어다 놓으면
`https://....netlify.app` 주소가 생깁니다. 그 주소를 거래처 담당자나 직원에게 보내면 됩니다.

- https 주소로 열면 Chrome 메뉴에 **앱 설치 / 홈 화면에 추가**가 나타나 일반 앱처럼 실행됩니다.
- **https 주소에서는 카메라 바코드 스캔이 바로 됩니다.** (권장)
- 이제 **로그인 화면**이 먼저 뜸니다. 계정(아이디·비밀번호)이 없으면 발주 화면은 열리지 않습니다. 직원 계정은 관리자가 만들어 **초대 링크**(카톡)로 나눠 줍니다 — 2번 참고.
- 발주 **자료**는 **각 휴대폰(브라우저)마다 따로** 저장됩니다(계정 목록만 구글 시트로 함께 맞춤). 한 직원이 낸 발주가 다른 직원 휴대폰에 보이지는 않습니다.

## 2. 로그인 · 직원 계정 (관리자 / 직원)

발주 화면을 열면 먼저 **로그인 화면**이 뜸니다. 아이디·비밀번호를 넣어야 발주 화면이 열리고, **로그인 유지**를 체크하면 그 휴대폰에서는 다음에 열 때 바로 들어갑니다(끄면 브라우저를 닫을 때 로그아웃).

- **관리자 계정**: 이 기기에서 처음 열면 관리자 계정 하나가 만들어집니다. 그 계정의 **처음 비밀번호는 로그인 화면에 적히지 않습니다**(따로 전달받아 쓰세요).
  → 들어간 뒤 오른쪽 위 **이름 칩(관리자)** → `내 비밀번호 바꾸기`에서 바로 바꾸세요.
- **초대 링크로 계정을 받은 기기에는 관리자 계정이 만들어지지 않습니다.** 그 기기에서는 직원 계정만 보이고, `사용자 관리`도 나오지 않습니다(링크로 관리자 권한이 새지 않음). 이미 관리자 계정이 있는 기기에서 링크를 열면 그 계정은 그대로 둡니다.
- **계정 목록은 구글 시트로 함께 맞춰집니다**(2-2). 피클·APK·카톡·삼성인터넷·크롬 어디로 열어도 같은 아이디·비밀번호로 들어갑니다. 시트가 막힌 곳에서는 이 기기에 저장된 계정으로 로그인하고, 초대 링크(2-1)로도 계정을 넣을 수 있습니다.
- 비밀번호는 평문으로 저장하지 않고 **SHA-256 해시**(계정마다 다른 salt)로 저장합니다. `file://`로 열어도 브라우저 보안 기능(`crypto.subtle`) 없이 같은 방식으로 동작합니다.

| 하고 싶은 일 | 어디서 |
| --- | --- |
| 로그아웃 · 다른 아이디로 | 오른쪽 위 **이름 칩** → `로그아웃` |
| 내 비밀번호 바꾸기 | 이름 칩 → 지금 비밀번호 + 새 비밀번호 두 번 → `내 비밀번호 바꾸기` |
| 직원 추가 | (관리자) 이름 칩 → `👥 사용자 관리` → 아이디·이름·비밀번호 → `직원 추가` |
| 직원 비밀번호 재설정 | 사용자 관리 → 그 직원 `비밀번호 재설정` → 새 비밀번호 → `저장` |
| 직원 삭제 | 사용자 관리 → `삭제` → `정말 삭제? (한 번 더)` |
| 직원 휴대폰에 계정 넣기 | 사용자 관리 → `초대 링크 복사`(직원별) 또는 `초대 링크 복사 (전체 직원)` → 카톡으로 보내기 |

### 2-1. 초대 링크로 직원 휴대폰에 계정 넣기

1. 관리자가 `👥 사용자 관리`에서 직원 계정을 만들고 **`초대 링크 복사`** 를 누릅니다.
2. 카톡으로 그 링크를 직원에게 보냅니다.
3. 직원이 휴대폰에서 링크를 열면 → **그 계정이 그 기기에 저절로 들어가고**, 로그인 화면에 아이디가 채워집니다. 비밀번호만 넣으면 바로 발주를 시작합니다.
4. 링크를 연 뒤 주소창의 `#invite=...` 부분은 자동으로 정리되어, 새로고침해도 다시 들어오지 않습니다.

- 링크 안에는 그 직원의 **아이디·이름·비밀번호 해시**가 들어 있습니다(평문 비밀번호 아님). 아무에게나 보내지 말고 해당 직원에게만 보내세요.
- 초대 링크는 **https 주소**(GitHub Pages·Netlify 등)로 열었을 때 쓸 수 있습니다. `file://`로 열어 복사한 링크는 다른 휴대폰에서 열리지 않으니, 직원 계정은 인터넷 주소로 배포한 화면에서 나눠 주세요.
- **관리자 비밀번호를 잊으면 되돌릴 수 없습니다**(서버가 없어서 재설정 메일 같은 것이 없습니다). 바꾼 비밀번호는 꼭 따로 적어 두세요. 잊었을 때는 브라우저 저장소를 지워 처음부터 다시 시작해야 하고, 그 기기의 발주 자료도 함께 지워집니다.
- **비밀번호를 잊었으면**: 관리자에게 재설정을 요청합니다. 화면의 `비밀번호를 잊었으면`은 그 안내만 보여 주고, 초기 비밀번호 같은 값은 화면에 찍지 않습니다.
- **관리자(admin) 계정은 링크에 담기지 않습니다.** 그래서 초대 링크로 관리자 권한이 새어 나가지 않고, 관리자가 자기 휴대폰에서 그 링크를 열어도 **자기 비밀번호는 그대로**입니다.
- 이미 그 기기에 같은 아이디가 있으면 **덮어쓰지 않습니다**(직원이 바꾼 비밀번호를 링크가 되돌리지 않음).

### 2-2. 관리자만 할 수 있는 일 / 직원도 할 수 있는 일

| 기능 | 관리자 | 직원 |
| --- | --- | --- |
| 발주(거래처·품목·바코드·사진·발주서·CSV) | O | O |
| 내 비밀번호 바꾸기 · 로그아웃 | O | O |
| 사용자 관리(직원 추가·비밀번호 재설정·삭제·초대 링크) | O | X (화면에 없고, 기능에서도 막힌다) |
| 관리자 계정 삭제 | X (삭제 버튼 없음) | X |
| 관리자 계정 자체가 있음 | O | X (초대받은 기기에는 만들지 않음) |

### 2-3. 직원마다 자료가 따로 저장됩니다

- 거래처·품목·발주 내역·설정은 **로그인한 아이디별로 따로** 저장됩니다(`kd.u.<아이디>.…`). 같은 휴대폰에서 admin으로 넣은 발주와 kim으로 넣은 발주가 섞이지 않습니다.
- 새 직원이 처음 로그인하면 **기본 품목 828개와 예시 거래처 3곳**이 그 직원 몫으로 새로 들어갑니다.
- 발주서(카톡·문자 복사)·CSV·발주 내역에 **`담당자: 이름(아이디)`** 가 함께 적혀, 누가 낸 발주인지 바로 보입니다.
- 로그인 없던 때 이 기기에 저장해 둔 자료가 있으면 **admin 계정 자료로 한 번 옮겨집니다**(잃지 않음).

### 2-4. 품목 목록은 암호화되어 있습니다

- 발주 화면 파일(`index.html`)과 GitHub 저장소에는 **품목 이름·바코드가 암호문으로만** 들어 있습니다. 로그인 전에는 품목이 하나도 보이지 않고, 페이지 소스를 뒤져도 품명·바코드가 나오지 않습니다.
- **관리자**가 그 기기에서 로그인하면 품목 828개가 풀려 목록에 들어갑니다. 관리자 비밀번호를 바꾸면 새 비밀번호로 다시 잠그므로, 다음에도 그 비밀번호로 열립니다.
- **직원**은 관리자가 보낸 **초대 링크에 품목 열쇠가 함께** 실려 옵니다. 링크를 연 기기에서 그 계정으로 로그인하면 828개 목록이 그대로 열립니다.
- 초대 링크에 열쇠가 없는 경우(예전에 만든 링크)나 열쇠가 지워진 기기에서는 로그인은 되지만 목록이 **`품목 잠김`** 으로 보입니다. 그때는 관리자에게 **새 초대 링크**를 받아 다시 열면 됩니다.
- **이번에 처음 열 때**: 예전에 발주 화면을 쓰던 기기는 열쇠가 아직 없어서 **딱 한 번 비밀번호로 다시 로그인**하라고 나옵니다(그 뒤로는 예전처럼 바로 들어갑니다). 관리자 비밀번호를 이미 바꿔 두었어도 **지금 쓰는 비밀번호**로 열립니다. 이미 저장된 품목·발주 내역은 그대로 있습니다.
- 열쇠는 이 기기(브라우저) 안에 계정별로 **감춘 형태**로 저장되고, 품목은 로그인한 그 계정의 저장 공간에만 펼쳐집니다.
- 초대 링크를 받은 사람은 그 링크 안의 열쇠로 목록을 열 수 있으니, 링크는 해당 직원에게만 보내세요.

## 2-2. 공용 계정 (구글 시트) — 다른 기기·다른 브라우저와 같은 아이디

계정 목록을 **구글 시트**(`계정목록` 시트의 `portal_users` 행)에 함께 두어, 피클·APK·카톡 인앱·삼성인터넷·크롬 어디로 열어도
업무일지·근태·포털과 같은 아이디·비밀번호·이름·결재 권한으로 들어갑니다.

- 로그인 화면이 열리면 조용히 한 번 계정 목록을 받아 오고, **이미 로그인된 상태로 앱을 열 때도** 조용히 한 번 확인합니다(60초 스로틀·실패 무소음). 이 기기에 없거나 비밀번호가 안 맞으면 한 번 더 받아 본 뒤 확인합니다. 시트가 안 되면 이 기기 계정으로 그대로 로그인합니다.
- 시트의 **이름·결재 권한**이 이 기기 계정과 다르면 로그아웃 없이 바로 바꿉니다(세션·화면 이름 포함).
- 지우기는 시트의 `deletedIds`(관리자가 실제로 삭제한 아이디)에 있는 계정만 지우고, 시트에 없다는 이유로 이 기기 계정을 지우지 않습니다(병합해 보존).
- 관리자가 직원을 추가·삭제하거나 비밀번호를 재설정할 때, 내가 내 비밀번호를 바꿀 때 시트에도 바로 올립니다.
- 시트에 실린 **품목 목록 열쇠(`kcat`)** 로 새 기기에서도 828개 품목이 바로 열립니다.
- 시트에는 salt·해시만 올라갑니다(평문 비밀번호 없음). 앱마다 해시 접두어가 달라 한 사람의 네 앱 해시를 함께 담습니다.
- **사용자별 메뉴(`menus`)** 는 포털 `사용자 관리`에서 정합니다. 이 앱은 그 값을 모르는 채로 계정 목록을 올리므로, 시트의 `menus` 를 **전체 저장(full)에서도 그대로 남기도록** 보존합니다(`syncKeepSheetMenus`).
- `내 계정`의 `🔐 통합 포털` 버튼은 로그인한 사람이면 누구나 보이고, `?stay=1` 로 포털에 돌아가 자기 메뉴를 다시 고를 수 있습니다.

## 3. 쓰는 순서

1. **거래처 선택** — 위쪽 드롭다운에서 고릅니다. 처음에는 예시 이름 3개(순천 ○○마트, 조례 △△식자재, 해룡 ☆☆반찬)가 들어 있습니다.
   - **품목은 거래처마다 따로 관리됩니다.** 거래처를 바꾸면 그 거래처 품목만 보입니다. (5번 참고)
2. **납품일** — 오늘 날짜로 맞춰져 있고, 눌러서 바꿀 수 있습니다.
3. **품목 담기**
   - **품목 선택** 탭: 검색창에 품명·규격·바코드를 치거나, 카테고리(담긴 품목만/전체/건어물/견과류/해조류/과자·간식/기타/행사상품)를 고른 뒤 수량 칸을 눌러 숫자를 바로 치거나 `+`로 올립니다. 단위는 `봉 / 박스 / 개` 중에서 고릅니다.
   - 품목이 828개라 처음에는 **60개씩** 보여 주고, 아래 **`더 보기`** 버튼을 누르면 60개씩 더 나옵니다. (휴대폰이 느려지지 않게 한 화면에 그리는 수를 제한했습니다. 검색·카테고리를 바꾸면 다시 60개부터 보여 줍니다.)
   - **바코드 스캔**: 검색창 옆 초록색 `바코드 스캔` 버튼을 누르고 상품 바코드를 비추면, 그 품목이 **1개 담기고** 카메라 화면에 `✓ 예시품목 (150g) 담김 · 현재 1봉` 이 뜹니다. **멈추지 않고 계속 찍을 수 있습니다** — 다음 상품으로 옮기면 바로 읽고, 아래 `방금 담은 품목`에 쌓입니다.
   - 다 찍었으면 **`스캔 완료 · 수량 입력하기`** 를 누릅니다. 자동으로 **담긴 품목만** 보이는 화면으로 넘어가서, 수량 칸을 눌러 `10`·`25`·`50`을 바로 칠 수 있습니다. (5번 참고)
   - **사진 찍어 발주** 탭: `사진 찍기`(카메라) 또는 `앨범에서`(여러 장 선택)로 매장의 상품을 찍고, 품명 메모와 수량만 적습니다.
4. **발주서 보기** — 아래쪽 초록 버튼. 품명·규격·수량·바코드가 표로 정리되고, 사진이 함께 붙습니다.
   - 표의 수량 칸에서도 `-`/`+`나 숫자 직접 입력으로 바로 고칠 수 있습니다.
   - **카톡·문자 복사**: 발주 내용이 글자로 복사됩니다 → 카톡 대화창에 붙여넣기. 맨 위에 `담당자: 이름(아이디)`가 들어갑니다.
   - **찍은 차례대로**: 확인 표와 복사·공유 글 모두 **바코드를 찍은 순서**대로 나옵니다(품목별 가나다·카탈로그 순서가 아닙니다). 같은 품목을 다시 찍으면 처음 찍은 자리를 지킵니다. 품명은 `예시품목 (150g)_8801234 56 7890` 처럼 **`품목 (규격)_바코드7자리 바코드2자리 바코드4자리`** 로 적히고, 바코드가 없는 사진 품목은 `_` 없이 나옵니다.
   - **엑셀(CSV) 저장**: `발주서_{거래처}_{날짜}.csv` 파일이 내려받아집니다. 엑셀에서 한글이 깨지지 않게 UTF-8(BOM)로 저장됩니다. `담당자` 칸도 함께 들어갑니다.
   - **공유하기**: 휴대폰 공유 창(카톡·문자·메일)으로 바로 보냅니다.
   - **발주 저장 (완료)**: 발주 내역에 쌓이고, 담아 둔 품목은 비워집니다.
5. **발주 내역** — 오른쪽 위 시계 아이콘. 지난 발주를 보고 **다시 발주**를 누르면 그때 품목이 그대로 다시 담깁니다(날짜는 오늘로).

### 3-1. 지난 발주 수량 한 번에 불러오기 (거래처별)

같은 거래처에 늘 비슷한 품목을 비슷한 수량으로 발주한다면, 지난번 수량을 그대로 불러와 고치기만 하면 됩니다.

1. 위쪽에서 **거래처를 고릅니다**. 품목 선택 탭 위에 그 거래처의 지난 발주가 한 줄로 보입니다 — 예: `순천 ○○마트 지난 발주 / 2026.11.20 · 2개 품목 · 수량 7`.
2. 초록 테두리 **`지난 발주 불러오기`** 버튼을 누릅니다. 그 거래처의 **가장 최근에 저장한 발주** 수량이 그대로 담깁니다. (`순천 ○○마트 마지막 발주(2026.11.20) 2개 품목 · 총 7개 불러왔어요`)
3. 품목 카드 오른쪽에 **`지난번 5봉`** 같은 회색 배지가 붙어, 그 거래처의 지난 발주에 있던 품목과 수량을 바로 알 수 있습니다. 거래처를 바꾸면 배지도 그 거래처 것으로 바뀝니다.
4. 이미 담아 둔 품목이 있으면 확인 창이 뜍니다.
   - **지금 담긴 것 지우고 불러오기** — 담아 둔 것을 비우고 지난 발주만 담습니다.
   - **담긴 품목에 합치기** — 겹치는 품목은 지난 수량으로 맞추고, 지난 발주에 없던 품목은 그대로 둡니다. (`진미채 1개`처럼 어제와 다르게 넣은 것 유지)
   - **취소**
5. 지난 발주에 있던 품목이 지금 품목 목록에 없으면(지운 품목 등) 건너뛰고 `목록에 없는 1개는 건너뛰었어요`라고 알려 줍니다. 지난 발주 내역이 아직 없으면 `이 거래처의 지난 발주 내역이 아직 없어요`라고만 안내합니다.

> 불러오는 수량은 **그 거래처의, 그 사용자(로그인 계정)의** 기록에서만 가져옵니다. 다른 거래처나 다른 직원의 발주와 섞이지 않습니다.

## 4. 거래처·품목 바꾸기 (거래처별 품목)

**품목 목록은 거래처마다 완전히 따로입니다.** 위쪽 드롭다운에서 거래처를 바꾸면 `품목 선택` 탭과 `+ 품목 추가·관리` 창에 그 거래처 품목만 나오고, 고친 내용도 그 거래처에만 적용됩니다.
담아 둔 수량(장바구니)도 거래처별로 따로 기억해서, 다른 거래처를 보다 돌아와도 담아 둔 것이 그대로 있습니다.

| 무엇을 | 어디서 |
| --- | --- |
| 거래처 추가 | `+ 거래처 추가` → 이름 입력 → `+` (또는 Enter). 새 거래처는 **품목이 빈 상태로 시작**합니다. |
| 거래처 이름 수정·삭제 | `관리` → 이름을 고치고 `✓` 저장, `🗑` 삭제 |

### 4-1. 대량 업로드 (엑셀·구글 시트에서 붙여넣기)

1. `+ 품목 추가·관리` → 맨 아래 **📥 대량 업로드 (엑셀/CSV)** 를 펼칩니다.
2. **양식 다운로드** — `품목양식_샘플.csv`(UTF-8 BOM)를 받아 엑셀에서 채웁니다.
   열 순서: `품명, 규격, 바코드, 카테고리, 기본단위`
3. **엑셀에서 복사해 붙여넣기** — 엑셀·구글 시트에서 행을 그대로 복사(Ctrl+C)해 입력칸에 붙여넣고 `붙여넣은 내용 등록`.
   - **탭으로 나뉜 줄(엑셀 복사)** 과 **쉼표로 나뉜 줄(CSV)** 둘 다 됩니다. 따옴표로 묶인 칸(`"테스트,상품"`)도 됩니다.
   - 첫 줄이 `품명/규격/바코드…` 머리글이면 자동으로 건너뜁니다.
   - 카테고리가 비었거나 목록에 없으면 `기타`, 단위가 비었으면 `봉`으로 들어갑니다.
   - **같은 바코드+품명인 줄은 그 품목을 고칩니다**(새로 만들지 않음). 바코드가 같아도 품명이 다르면 **새 품목으로 들어갑니다** — 가격 내장 `2…` 바코드를 여러 상품이 함께 쓰기 때문입니다(5-5).
4. **CSV 파일 올리기** — 엑셀에서 `CSV UTF-8`로 저장한 파일을 고릅니다. 한글 엑셀 기본값(ANSI/CP949)으로 저장한 파일도 읽습니다.
5. 넣은 결과는 `품목 3개 추가 · 1개 수정` 처럼 알려 줍니다. **넣는 곳은 지금 선택된 거래처**입니다.

> **기본 품목 828개**(바코드 정리본)가 거래처 3곳에 각각 들어 있습니다. 서로 별개이므로 한 곳에서 고쳐도 다른 곳은 그대로입니다. 필요 없는 거래처 품목은 지우고 쓰세요.
> 예전에 앱을 열어 예시 품목이 저장돼 있던 기기라면, 처음 열 때 **예시 품목만 걷어내고 전체 목록으로 바꿉니다.** 직접 넣은 품목은 그대로 남습니다.

## 5. 바코드 스캔

### 5-1. 카탈로그에서 찍기 (연속으로 담기)

- 검색창 옆 **바코드 스캔** 버튼 → 카메라 화면이 열립니다. 바코드를 네모 안에 맞추면 자동으로 읽습니다.
- **한 번 찍으면 카메라가 계속 켜져 있습니다.** `계속 스캔`을 누를 필요 없이 다음 상품 바코드를 비추면 바로 담깁니다.
  - 소리가 나고(삐) 짧게 진동합니다.
  - 카메라 화면 위에 `✓ 예시품목 (150g) 담김 · 현재 1봉` 처럼 잠깐 떴다 사라지는 안내가 나옵니다. 이 안내는 화면을 가리지 않습니다.
  - 화면 아래 **`방금 담은 품목 (3종)`** 목록에 담은 것이 차례로 쌓입니다. 목록에서 바로 `-`/`+` 하거나 숫자를 직접 넣어 고칠 수 있습니다.
  - **같은 바코드를 계속 비추고 있을 때만** 약 1.8초에 한 번씩 셉니다(카메라를 들고 흔들려도 수량이 막 늘지 않게). **다른 상품으로 옮기면 기다리지 않고 바로 읽습니다.**
  - 같은 상품을 한 번 더 담고 싶으면 1.8초 뒤에 다시 비추거나, 아래 목록의 `+`를 누르면 됩니다.
- 다 찍었으면 아래쪽 초록색 **`스캔 완료 · 수량 입력하기`** 를 누릅니다 → 4-2로 넘어갑니다. (`닫기`를 누르면 그냥 카탈로그로 돌아갑니다.)
- 카메라 화면 바로 아래의 **`사진으로 바코드 읽기` · `여러 장 한 번에 읽기`** 버튼은 담은 품목이 쌓여도 **목록 위에 그대로 있습니다.** 사진으로 찍을 때도 아래 같은 방식으로 이어서 찍습니다(4-4).
- **찍은 순서가 그대로 남습니다.** 바코드를 찍어 담은 차례대로 `담긴 품목만` 목록과 발주서 확인 표, 카톡으로 보낼 글이 나옵니다(3번 `발주서 보기`의 `찍은 차례대로`).
- **이 거래처에는 없는데 다른 거래처에 있는 품목**이면, 그 품목 이름·규격과 함께 **`이 거래처 품목에 바로 추가`** 버튼이 뜹니다. 한 번 누르면 이 거래처 품목으로 등록되고 1개 담기며, 스캔은 계속됩니다.
- **같은 바코드를 쓰는 품목이 여럿이면**(2로 시작하는 가격 내장 바코드) **후보 선택 창**이 뜹니다 — 하나를 누르면 바로 담기고 스캔이 이어집니다(5-5).
- 어느 거래처에도 없으면 `미등록 바코드: 1234…` 안내와 **`이 바코드로 새 품목 등록`** 버튼이 뜹니다. 누르면 품목 관리 창이 열리고 바코드가 채워진 채 **품명 칸에 커서**가 갑니다. 그냥 지나가면 스캔은 멈추지 않고 계속됩니다.

### 5-2. 스캔 완료 후 수량 입력 (담긴 품목만)

- `스캔 완료 · 수량 입력하기`를 누르면 **담긴 품목만** 보이는 화면으로 바뀝니다. 828개 전체 목록 대신, 지금 장바구니에 담겨 있는 품목만 나옵니다. (사진·번호 직접 입력으로 담은 것도 함께)
- 각 품목의 **수량 칸(숫자)을 누르고 `10`, `25`, `50`을 그대로 칩니다.** `+`를 스물다섯 번 누를 필요가 없습니다. `-`/`+`도 그대로 됩니다.
- 0으로 지우면 그 품목은 목록에서 빠집니다.
- **`전체 품목 다시 보기`** 를 누르면 언제든 828개 전체 목록으로 돌아갑니다.
- 카테고리 줄 맨 앞의 **`담긴 품목만 (3)`** 알약을 눌러도 같은 화면을 켜고 끌 수 있습니다. (개수가 실시간으로 바뀝니다.)
- 발주서 화면(`발주서 보기`)에서도 표의 수량 칸을 눌러 바로 고칠 수 있고, 위아래 `-`/`+`도 됩니다. 고친 값은 카톡 복사·CSV 저장 내용에 바로 반영됩니다.

### 5-3. 품목 관리에서 찍기 (등록)

- `+ 품목 추가·관리` → 바코드 칸 옆 **스캔** 버튼으로 바코드를 채웁니다.
- 이미 이 거래처에 있는 품목이면 품명·규격까지 자동으로 채워 줍니다. 다른 거래처에만 있던 품목이면 그 정보를 채우고, 완전히 새 바코드면 바코드만 채웁니다.
- **`저장 후 다음 바코드 스캔`** 버튼을 쓰면 `품명 적기 → 저장 → 다음 바코드 찍기`를 반복해서 여러 품목을 연달아 등록할 수 있습니다.

### 5-4. 카메라가 안 될 때 (중요)

휴대폰에서 **파일(file://)로 열었거나**, 브라우저가 바코드 인식을 지원하지 않으면 실시간 카메라가 막힙니다.
그래도 스캔 창에는 항상 사진 버튼 두 개가 **카메라 화면 바로 아래, 담은 품목 목록 위에** 있습니다.

1. **`사진으로 바코드 읽기`** — 누르면 휴대폰 카메라가 바로 열립니다. 바코드를 찍으면 사진에서 바코드를 읽어 1개 담습니다. 사진이 옆으로 누워 있어도 찾습니다.
2. **`🖼️ 여러 장 한 번에 읽기`** — 앨범에서 사진을 **여러 장 고르면 한 장씩 차례로 읽어 담습니다.** `사진 3/5장에서 바코드를 찾는 중…` 처럼 진행이 보이고, 끝나면 `사진 5장 중 4장에서 바코드를 읽어 담았습니다` 로 알려 줍니다. 못 읽은 사진 수와 담긴 품목 목록도 함께 보여 줍니다.
3. **`바코드 번호 직접 입력`** — 바코드 아래 숫자를 그대로 치고 `확인`.

**사진으로 읽은 뒤에는 안내 칸의 `📷 다음 바코드 찍기`를 누르면 바로 다음 바코드를 찍습니다.** 한 번 누르는 것만으로 휴대폰 카메라가 열립니다(사진 고르는 창을 거치지 않습니다).

- 안내 칸에 `✓ 예시품목 (150g) +1 담김 · 현재 1봉 · ‘다음 바코드 찍기’를 누르세요` 처럼 뜨고, 바로 아래에 큰 **`📷 다음 바코드 찍기`** 버튼이 있습니다. 이어서 `수량 입력하기` · `닫기`가 있습니다.
- 사진에서 바코드를 못 찾으면 안내 칸이 `바코드를 찾지 못했습니다 · 바코드가 크게 보이게 다시 찍어 보세요` 로 바뀌고, **거기서도 `📷 다음 바코드 찍기`를 바로 누를 수 있습니다.**
- 여러 장을 한 번에 읽었을 때는 안내 칸에 `✓ 2장에서 바코드를 읽어 담았습니다`(못 읽은 장이 있으면 그 수도)가 뜨고, 역시 `다음 바코드 찍기`로 이어서 찍을 수 있습니다.
- 카메라가 되는 환경(Chrome·https)에서는 예전처럼 카메라가 계속 켜져 있어 `다음 바코드 찍기` 버튼 없이 `수량 입력하기`가 첫 버튼입니다.

**실시간 스캔을 쓰려면** Chrome에서 열거나, `https://` 주소(방법 B)로 열면 됩니다.
카메라는 기기 안에서만 쓰고, 사진은 서버로 보내지 않습니다.

### 5-5. 같은 바코드(공통 바코드) · 2로 시작하는 가격 내장 바코드

`2`로 시작하는 13자리 바코드(예: `2999900`으로 시작하는 `2999900099001`)는 **가격이 바코드 안에 들어 있어서**, 같은 가격대 상품이 같은 번호를 쓰고 가격이 바뀌면 뒤 6자리가 달라집니다. 그래서 품목에 같은 바코드를 여러 개 넣을 수 있게 하고, 찍었을 때 **후보에서 한 번 눌러 고르게** 했습니다.

- **같은 바코드 허용**: 품목 추가·수정, 엑셀/CSV 대량 업로드, 다른 거래처 품목 복사에서 **같은 바코드를 막지 않습니다.** (대량 업로드는 `같은 바코드 1종 허용` 처럼 알려 줍니다. 같은 바코드+품명인 줄만 그 품목을 고칩니다.)
- **찾는 순서**: ① 지금 거래처에서 **바코드가 똑같은 품목** → ② 바코드가 `2`로 시작하면 **앞 7자리가 같은 품목**(같은 가격대). 같은 품목이 두 번 들어가지 않게 합쳐서 셉니다.
- **1개만 맞으면**: 예전처럼 창 없이 바로 `+1` 담기고 `방금 담은 품목`에 쌓입니다.
- **2개 이상 맞으면**: **`어느 품목에 담을까요?`** 창이 뜨고 후보가 **`이 바코드`(똑같은 번호) 먼저, `같은 가격대`(앞 7자리) 다음** 순서로 나옵니다. 품명·규격·카테고리·바코드와 **`지난번 N개`** 배지가 함께 보입니다.
- **한 번만 누르면 끝**: 후보 줄을 누르면 바로 `+1` 담기고, `방금 담은 품목`·상단 수량·토스트가 한 번에 바뀝니다. 카메라 스캔 중이면 창이 닫히고 **스캔이 그대로 이어집니다**(같은 바코드가 화면에 남아 있어도 2.2초 동안은 다시 뜨지 않음).
- **가격이 바뀌어도**: `2999900099001` → `2999900099018` 처럼 뒤 6자리가 달라져도 앞 7자리(`2999900`)가 같으면 같은 후보가 나옵니다.
- **한 개도 없으면**: 예전과 같은 `미등록 바코드` 안내와 `이 바코드로 새 품목 등록` 버튼이 나옵니다.
- 사진 여러 장을 한 번에 읽는 중에 후보가 생기면, 담고 나서 **다음 사진의 후보가 이어서** 뜨므로 건너뛰지 않습니다.

## 9. 개발 메모

- **로그인·계정**은 `index.html` 안에서만 동작합니다(서버 없음). `kd.users.v1`에 계정 목록, `kd.session.v1`(또는 sessionStorage `kd.session.tmp.v1`)에 로그인 상태를 둡니다.
- 비밀번호는 `SHA-256('kd1|' + salt + '|' + 비밀번호)` 해시로만 저장합니다. `crypto.subtle`은 `file://`에서 막히는 경우가 있어 **순수 JS SHA-256**을 넣었고, 표준 해시와 같은 값이 나오는지 검증했습니다.
- 화면을 그리기 전에 로그인 게이트를 먼저 통과합니다. 로그인하면 `setScope(아이디)`가 저장 키를 `kd.u.<아이디>.…`로 바꾸고 그때 `load()`를 부릅니다. 로그아웃은 세션을 지우고 새로고침합니다(메모리 상태까지 깨끗하게).
- 관리자 기능은 화면에서 숨기는 것과 별개로 `addUser`·`resetPassword`·`deleteUser` 안에서 `isAdmin()`을 다시 확인합니다. `admin`은 삭제되지 않고, 초대 링크에도 담기지 않습니다.
- 초대 링크는 `#invite=<base64url(JSON)>`입니다. 링크를 열면 계정을 넣고 `history.replaceState`로 해시를 지웁니다. 이미 있는 아이디는 덮어쓰지 않습니다. 링크에는 그 직원 몫의 **감싼 품목 열쇠**(`cat`)도 함께 들어갑니다.
- **품목 목록 암호화**: `K_cat`(32자 hex)을 키로 `sha256_hex(K_cat + '|' + 블록번호)` 키스트림을 만들어 평문과 XOR합니다(파일마다 같은 값, `file://`에서도 동작). `K_cat`은 파일에 평문으로 넣지 않고, ① 관리자 초기 비밀번호에서 `sha256('kdw1|salt|pw')`를 4096번 돌린 키, ② 계정의 `salt+해시`에서 만든 키(`kdi1|salt|hash`), 두 가지로만 감싸 둡니다. 그래서 로그인 전에는 열쇠를 만들 수 없습니다. 관리자 비밀번호를 바꾸면 ②를 새 해시로, ①을 새 비밀번호로 다시 감쌉니다. 관리자가 쓰는 기기(이 기기에 admin 계정과 열쇠가 있음)에서는 직원 계정도 ②로 열쇠를 받습니다.
- 품목을 푸는 시점은 `tryLogin()`과 `startApp()`(로그인 유지로 다시 열 때)입니다. 잠긴 채면 `CAT.ok=false`라 `renderCatalog()`가 `품목 잠김`을 보여 주고, `load()`도 기본 품목을 저장하지 않습니다.
- 담당자는 `buildOrderText()`·`buildCSV()`·`saveOrder()`에 로그인 사용자를 넣어 만들고, 발주 내역 카드에도 함께 보입니다.
- 단일 HTML 파일. 인라인 SVG 아이콘, 시스템 한글 글꼴, 외부 CDN·라이브러리 없음(바코드도 브라우저 내장 `BarcodeDetector`만 사용, 비용 없음).
- 바코드 지원 형식: EAN-13 / EAN-8 / UPC-A / UPC-E / Code128 / Code39 / QR.
- 연속 스캔 쿨다운은 **바코드별** 1.8초(`BC_COOL`). 인식 루프는 200ms 간격으로 프레임을 보고, 같은 바코드가 화면에 남아 있을 때만 쿨다운으로 거릅니다. 미등록 안내는 같은 바코드에 2.6초(`BC_UK_COOL`)에 한 번만 뜍니다.
- 사진 버튼(`.scanphoto`)은 `#bc-stage`/`#bc-hit` 아래·`#bc-added` 위에 둡니다. 목록(`#bc-added-list`)은 `max-height:32vh` 로 자체 스크롤되고, 패널 본문이 스크롤돼도 사진 버튼이 목록보다 위에 있습니다. 카메라가 막히면 `.scanstage.off` 가 높이 104px로 줄어 사진 버튼·안내·목록이 한 화면에 더 들어갑니다.
- `📷 다음 바코드 찍기`는 `bcShowHit()`의 act에 `{ for:'bc-file' }` 를 넘겨 `<label for="bc-file">` 로 그립니다(스크립트 `.click()` 은 사용자 제스처가 아니라 카메라가 막힘). 노출 조건은 `SCAN.mode !== 'item' && !SCAN.stream` (`bcPhotoNext()`), 이때 `수량 입력하기`는 `btn soft` 로 내립니다. 세 버튼은 `.acts` 에서 `flex-wrap`, 다음 찍기는 `.btn.full`(한 줄 전체).
- 여러 장 읽기는 `bcDecodeFileAsync()` 를 파일 수만큼 **순서대로** 기다리며 파일마다 `bcHandle(code, 'photo')` 를 부릅니다. 끝나면 요약 안내(`bcShowHit`)로 덮어씁니다(못 읽은 장 수 포함). 읽는 중에는 `SCAN.multiBusy` 로 중복 선택을 막습니다.

- **같은 바코드 후보**는 `bcCandidates(code)` 가 `G.items` 를 한 번 훑어 **정확 일치(`bcMatchBarcode`, 12/13자리 앞 0 허용)** 를 먼저, 이어서 **같은 7자리 묶음(`bcSameGroup`)** 을 `seen[id]` 로 중복 없이 모아 `{all, exact, group}` 을 돌려줍니다. `bcHandle()` 은 1개면 `bcAddItem()`+`bcAfterAdd()`, 2개 이상이면 `bcPickOpen()` 으로 갈라집니다. 후보 창(`#modal-bc-pick`, `z-index:70`)은 스캔 창 위에 겹쳐 뜨고, 고르면 `bcPickDone()` 이 닫은 뒤 `bcResumeScan()` 으로 인식 루프를 다시 켭니다. 사진 여러 장 중 밀린 바코드는 `PICK.pend` 에 쌓아 이어서 처리하고, 담은 직후 같은 바코드는 `SCAN.pickHold`(2.2초)로 걸러 냅니다.
